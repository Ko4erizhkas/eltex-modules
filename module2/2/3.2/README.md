# 3.2 — Принятие решения при отправке пакета IPv4

Программа имитирует то, что делает узел перед отправкой пакета: сравнивает
адрес назначения с собственной подсетью и решает, отдавать пакет напрямую
или на шлюз. Адреса назначения генерируются случайно, по итогам выводится
статистика.

## Сборка и запуск

```
make
./ipnet.exe <IP шлюза> <маска подсети> <количество пакетов>
./ipnet.exe 192.168.1.1 255.255.255.0 100
```

Вывод в консоли — UTF-8, `main.c` переключает кодовые страницы, поэтому
программа привязана к Windows.

## Файлы

| Файл | Назначение |
|---|---|
| `ipnet.h` | API работы с адресами |
| `ipnet.c` | Разбор, вывод, проверка маски, сравнение подсетей, генерация |
| `main.c` | Разбор аргументов, цикл обработки пакетов, статистика |
| `tests/` | Юнит-тесты на Unity |

## Представление адреса

Адрес хранится в одном `unsigned` — 32 бита, старший октет слева:

```
192.168.1.1  ->  11000000 10101000 00000001 00000001  ->  0xC0A80101
```

В таком виде принадлежность подсети — это одно сравнение:

```c
(dest & mask) == (gateway & mask)
```

Адрес сети и широковещательный адрес отдельно не исключаются: для решения
«свой/чужой» это неважно, а под задачу «сколько пакетов ушло в свою подсеть»
они считаются такими же адресами.

## Аргументы и их проверка

| Аргумент | Формат | Проверка |
|---|---|---|
| IP шлюза | `a.b.c.d` | четыре октета, каждый не больше 255 |
| Маска | `a.b.c.d` | то же плюс непрерывность единиц |
| Количество | целое | `strtol` до конца строки, больше нуля |

Префиксная запись маски (`/24`) не поддерживается — только точечная.

Маска считается корректной, если это непрерывная последовательность единиц
слева. Проверка держится на том, что у такой маски инверсия имеет вид
`000...111`, а у числа вида `2^n - 1` нет общих единиц с числом на единицу
больше:

```c
unsigned inv = ~mask;
return (inv & (inv + 1)) == 0;
```

Поэтому `255.255.255.0` проходит, а `255.0.255.0` отбрасывается.

## Генерация адресов

`RAND_MAX` в MinGW равен 32767, то есть один вызов `rand()` даёт всего 15
битов, и старшая половина адреса всегда была бы нулевой. Поэтому адрес
собирается побайтово, четырьмя вызовами:

```c
for (i = 0; i < 4; i++)
    addr = (addr << 8) | (unsigned)(rand() & 0xFF);
```

Генератор инициализируется `srand(time(NULL))`, поэтому два запуска в пределах
одной секунды дадут одинаковую последовательность адресов.

Адреса берутся из всего диапазона, никакие служебные диапазоны (0.0.0.0/8,
127.0.0.0/8, multicast) не исключаются.

## Примеры работы

### Пять пакетов при маске /24

```
> ./ipnet.exe 192.168.1.1 255.255.255.0 5

Своя подсеть: 192.168.1.0

Пакет 1: 146.27.0.2      - другая сеть (через шлюз)
Пакет 2: 92.221.158.190  - другая сеть (через шлюз)
Пакет 3: 160.229.74.176  - другая сеть (через шлюз)
Пакет 4: 47.81.251.253   - другая сеть (через шлюз)
Пакет 5: 97.168.107.140  - другая сеть (через шлюз)

Всего пакетов: 5
Своя подсеть:  0 шт. (0.00%)
Другие сети:   5 шт. (100.00%)
```

Ни одного попадания — и это ожидаемо: при маске `255.255.255.0` своей подсети
принадлежит 256 адресов из 2^32, то есть примерно один пакет из 16 миллионов.
Чтобы попадания были видны, нужна короткая маска и много пакетов.

### Тысяча пакетов при маске /8

```
> ./ipnet.exe 10.0.0.1 255.0.0.0 1000

Своя подсеть: 10.0.0.0
...
Пакет 226: 10.48.139.72    - своя подсеть
...
Всего пакетов: 1000
Своя подсеть:  3 шт. (0.30%)
Другие сети:   997 шт. (99.70%)
```

Доля своих пакетов сходится к доле подсети в адресном пространстве: для `/8`
это 1/256 ≈ 0.39%.

### Отказы

```
> ./ipnet.exe 10.0.0.1 255.0.255.0 100
Ошибка: некорректная маска подсети

> ./ipnet.exe 10.0.0.1 255.255.255.0 abc
Ошибка: количество пакетов должно быть целым числом больше нуля
```

## Тесты

```
cd tests
make test
```

Весь API `ipnet.c` публичный, поэтому файл линкуется как обычно, включать `.c`
в тест не требуется. Вывода в модуле нет, подменять `stdin`/`stdout` не нужно.

Покрыты: разбор адреса (значение числа, границы `0.0.0.0` и
`255.255.255.255`, старший октет больше 127, отказы на лишних и недостающих
октетах, октете больше 255 и мусоре в конце), вывод и его обратимость с
разбором, проверка маски на непрерывность единиц, принадлежность подсети
(включая маски `0.0.0.0` и `255.255.255.255` и расширение маски, объединяющее
две сети), а также генератор — что он не выдаёт одно и то же значение и что
за серию вызовов встречается единица в каждом из 32 битов.
