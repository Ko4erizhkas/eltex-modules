# 6.3 — Калькулятор с операциями из динамических библиотек

Переработка 2.3: ни одной операции внутри программы нет. При запуске
считывается каталог с библиотеками, из каждой достаётся функция, и меню
строится по тому, что нашлось.

## Сборка и запуск

```
make
./calc.exe
```

Каталог по умолчанию — `plugins`, путь относительный, поэтому запускать нужно
из каталога задания. Свой каталог передаётся первым аргументом:

```
./calc.exe ../other_plugins
```

## Файлы

| Файл | Назначение |
|---|---|
| `plugin.h` | Договор между программой и библиотекой операции |
| `loader.h`, `loader.c` | Обход каталога, загрузка библиотек, таблица операций |
| `calc.h`, `calc.c` | Меню, построенное по таблице |
| `main.c` | Точка входа, отчёт о загруженном |
| `plugins/*.c` | Операции, по одной на библиотеку |
| `tests/` | Юнит-тесты на Unity |

## Контракт плагина

Библиотека экспортирует ровно одну функцию `op_apply` и строку `op_name`
для меню. Плагин целиком выглядит так:

```c
#include "plugin.h"

OP_EXPORT const char op_name[] = "Сложение (+)";

OP_EXPORT double op_apply(double n1, double n2)
{
    return n1 + n2;
}
```

`OP_EXPORT` разворачивается в `__declspec(dllexport)` на Windows и в пустоту
на Linux.

Добавить операцию можно, просто положив новый `.dll`/`.so` в каталог —
программа не перекомпилируется.

## Загрузчик

Каталог обходится через `opendir`/`readdir` (`dirent.h` есть и в MinGW,
и в Linux), берутся файлы с подходящим расширением, из каждого достаются оба
символа. Различия систем спрятаны в четыре обёртки:

| | Windows | Linux |
|---|---|---|
| открыть | `LoadLibraryA` | `dlopen(..., RTLD_NOW)` |
| символ | `GetProcAddress` | `dlsym` |
| закрыть | `FreeLibrary` | `dlclose` |
| расширение | `.dll` | `.so` |

Если в файле нет `op_name` или `op_apply`, библиотека закрывается и
пропускается с сообщением — программа не падает.

Загруженные операции сортируются по имени файла: `readdir` порядок обхода не
гарантирует, а нумерация в меню не должна меняться между запусками. Отсюда
числовые префиксы `01_`…`04_` — они и задают порядок `+ - * /`.

## Что заменило массив указателей из 2.3

В 2.3 операции лежали в массиве, заполненном на этапе компиляции. Здесь тот же
массив собирается во время выполнения из того, что нашлось на диске, а вызов
остаётся таким же — через указатель на функцию.

## Тесты

```
cd tests
make test
```

Загрузчик работает с настоящими файлами, поэтому `Makefile` тестов собирает
каталог `fixtures` из трёх библиотек: две корректные и одна без нужных
символов.

Покрыты: загрузка только корректных библиотек (кривая пропускается), чтение
имени из библиотеки, сортировка по имени файла, вызов загруженных функций,
отсутствующий каталог, каталог без библиотек, `NULL`-аргументы, выгрузка и
повторная загрузка. Отдельно проверяются настоящие `plugins`: четыре операции
и правильная арифметика — если каталог ещё не собран, тесты отмечаются
пропущенными, а не падают.
