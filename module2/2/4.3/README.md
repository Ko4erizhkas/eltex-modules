# 4.3 — Телефонная книга на двоичном дереве поиска

Переработка телефонной книги из 2.1: контакты хранятся в двоичном дереве
поиска с периодической балансировкой. Ключ — Ф.И.О., как и в 4.1.

## Сборка и запуск

```
make
./pb.exe
```

При старте книга заполняется восемью тестовыми контактами. Вывод в консоли —
UTF-8, `main.c` переключает кодовые страницы, поэтому программа привязана
к Windows.

## Файлы

| Файл | Назначение |
|---|---|
| `phoneBook.h` | Типы данных и API дерева |
| `phoneBook.c` | Дерево, балансировка, ввод/вывод, меню |
| `main.c` | Точка входа, настройка кодировки консоли |
| `tests/` | Юнит-тесты на Unity |

## Модель данных

```
PhonebookTree            — книга (root, size, opsSinceBalance)
  └── PHNode             — узел (parent, left, right, data)
        └── Contact      — контакт (Ф.И.О. + массивы номеров и соцсетей)
```

Контакт лежит в узле по значению: одна аллокация на контакт, `free(node)`
освобождает всё разом. Порядок задаёт `contact_cmp` — фамилия, затем имя,
затем отчество; контакты с одинаковым Ф.И.О. уходят вправо, поэтому порядок
их добавления сохраняется.

| Операция | Сложность | Описание |
|---|---|---|
| `phtree_insert` | O(h) | Спуск от корня и подвешивание нового узла |
| `phtree_erase` | O(h) | Удаление узла, три случая по числу детей |
| `phtree_at` | O(n) | Узел по номеру в обходе слева направо |
| `phtree_reposition` | O(h) | Перестановка после правки Ф.И.О. |
| `phtree_balance` | O(n) | Полное перестроение в идеально сбалансированное |
| `phtree_height` | O(n) | Текущая высота |

## Удаление и перестановка

У узла с двумя детьми в него копируются данные преемника — самого левого узла
правого поддерева, — а физически удаляется преемник, у которого левого ребёнка
заведомо нет. Отсюда важное для вызывающего кода следствие: `phtree_erase`
может освободить не тот узел, который ему передали.

Поэтому `phtree_reposition` сначала копирует контакт в локальную переменную,
затем удаляет узел и вставляет копию заново. После него старый указатель на
узел недействителен.

## Балансировка

`phtree_maybe_balance` вызывается после каждой вставки и удаления, но реально
что-то делает раз в `BALANCE_PERIOD` (8) изменений: считает высоту и
перестраивает дерево, только если она больше `BALANCE_FACTOR` (2) идеальных
высот. Иначе счётчик просто сбрасывается, и O(n)-перестроение не тратится
впустую.

Само перестроение: обход слева направо собирает узлы в массив, дальше середина
отрезка рекурсивно становится корнем поддерева. Память под узлы не выделяется
заново — переписываются только связи, поэтому указатели на узлы переживают
балансировку.

Тестовые контакты дают высоту 5 при идеальной 4 — порог не превышен, и
автоматического перестроения не будет. Чтобы увидеть срабатывание, добавьте
несколько контактов подряд по алфавиту: дерево выродится в список, и на
очередной проверке появится строка `[Дерево перестроено: ...]`.

## Меню

| Пункт | Действие |
|---|---|
| 1–4 | Добавить, удалить, изменить, вывести контакты — как в 4.1 |
| 5 | Структура дерева: размер, высота, порог, само дерево на боку |
| 6 | Принудительная балансировка с высотой до и после |
| 0 | Выход |

## Примеры работы

### Структура дерева на тестовых данных

```
1. Добавить контакт
2. Удалить контакт
3. Изменить контакт
4. Вывести все контакты
5. Показать структуру дерева
6. Сбалансировать дерево
0. Выйти
Выберите действие: 5

-----------------------
Контактов: 8
Высота дерева: 5 (идеальная 4, порог 8)
Изменений с последней проверки: 0 из 8
-----------------------
        Сидоров Алексей
                Соколова Екатерина
            Смирнов Дмитрий
    Петрова Мария
            Морозов Сергей
        Кузнецова Ольга
Иванов Иван
    Волкова Анна
```

Дерево повёрнуто на 90 градусов: корень слева, правое поддерево сверху,
левое снизу. Корнем стал Иванов — он добавлялся первым.

### Принудительная балансировка

```
Выберите действие: 6

Высота дерева: 5 -> 4

Выберите действие: 5

-----------------------
Контактов: 8
Высота дерева: 4 (идеальная 4, порог 8)
Изменений с последней проверки: 0 из 8
-----------------------
        Соколова Екатерина
    Смирнов Дмитрий
        Сидоров Алексей
Петрова Мария
        Морозов Сергей
    Кузнецова Ольга
        Иванов Иван
            Волкова Анна
```

Корнем стала Петрова — середина упорядоченного списка контактов. Порядок
обхода не изменился, пункт 4 выдаёт те же восемь контактов по алфавиту.

## Тесты

```
cd tests
make test
```

Часть функций объявлена `static`, поэтому тест включает `phoneBook.c` целиком.

Покрыто дерево: инвариант порядка, согласованность ссылок на родителя, все три
случая удаления (лист, один ребёнок, два ребёнка), удаление корня и последнего
узла, перестановка после правки ключа, высота и идеальная высота,
перестроение (включая то, что узлы переиспользуются), а также сама
периодическая балансировка — что на восьми узлах она ещё не срабатывает,
а на шестнадцати вырожденное дерево перестраивается до высоты 5.

Ввод контакта, редактирование и удаление номеров и соцсетей с задания 4.1 не
менялись и покрыты тестами там.
