# 4.1 — Телефонная книга на двусвязном упорядоченном списке

Переработка телефонной книги из задания 2.1: хранение контактов переведено с
массива фиксированного размера на двусвязный список, узлы которого всегда
упорядочены по Ф.И.О.

## Сборка и запуск

```
make
./pb.exe
```

Собирается вручную:

```
gcc -Wall -Wextra phoneBook.c main.c -o pb.exe
```

При старте книга заполняется восемью тестовыми контактами (`fillTestData`),
чтобы меню было на чём проверять.

Вывод в консоли — UTF-8. `main.c` переключает кодовые страницы консоли через
`SetConsoleCP`/`SetConsoleOutputCP`, поэтому программа привязана к Windows.

## Файлы

| Файл | Назначение |
|---|---|
| `phoneBook.h` | Типы данных и публичный API списка |
| `phoneBook.c` | Реализация списка, ввод/вывод/редактирование, меню |
| `main.c` | Точка входа, настройка кодировки консоли |
| `Makefile` | Сборка |

## Модель данных

Три уровня вложенности:

```
PhonebookList          — сама книга (head, tail, size)
  └── PHNode           — узел списка (prev, next, data)
        └── Contact    — контакт (Ф.И.О. + массивы номеров и соцсетей)
              ├── Numbers phonenumber[4]
              └── Social  social[4]
```

`Contact` лежит в узле **по значению**, а не по указателю. Это даёт одну
аллокацию на контакт: `malloc(sizeof(PHNode))` выделяет память и под узел, и
под данные, а `free(node)` освобождает всё разом. Потерять контакт при
удалении узла невозможно. Такое решение работает потому, что `Contact` имеет
фиксированный размер — внутри только массивы, никаких собственных указателей.

Сам список выглядит так:

```
NULL <- prev                                            next -> NULL
        ┌──────┐      ┌──────┐      ┌──────┐      ┌──────┐
head -> │ Волк │ <--> │ Иван │ <--> │ Кузн │ <--> │ Моро │ <- tail
        └──────┘      └──────┘      └──────┘      └──────┘
```

### Ограничения размеров

| Константа | Значение | Что ограничивает |
|---|---|---|
| `MAX_SIZE` | 128 | длина Ф.И.О., номера, ника, названия соцсети |
| `MAX_SIZE_LINK` | 512 | длина ссылки на профиль |
| `MAX_COUNT` | 4 | номеров и соцсетей на один контакт |
| `MAX_COUNT_CONTACTS` | 8 | только количество тестовых контактов |

Число контактов в книге не ограничено — список растёт динамически.
`MAX_COUNT_CONTACTS` остался от версии на массиве и теперь используется лишь
в `fillTestData`.

## Порядок сортировки

`contact_cmp()` сравнивает контакты по фамилии, при равенстве — по имени, затем
по отчеству. Возвращает результат в стиле `strcmp`: отрицательное, ноль,
положительное.

Это единственное место, где задан порядок книги. Чтобы сортировать иначе,
достаточно переписать эту функцию — остальной код её не знает.

## Инварианты списка

Их нарушение — источник практически всех багов в списках, поэтому каждая
операция обязана их сохранять:

```
пустой список  ->  head == NULL && tail == NULL && size == 0
один узел      ->  head == tail && head->prev == NULL && head->next == NULL
всегда         ->  head->prev == NULL
                   tail->next == NULL
                   node->prev->next == node    (если prev != NULL)
                   node->next->prev == node    (если next != NULL)
упорядоченность->  contact_cmp(&node->prev->data, &node->data) <= 0
```

## API списка

| Функция | Сложность | Описание |
|---|---|---|
| `phlist_init` | O(1) | Создать пустую книгу |
| `phlist_free` | O(n) | Удалить все узлы и саму книгу, обнулить указатель |
| `phlist_insert` | O(n) | Вставить копию контакта на своё место по порядку |
| `phlist_at` | O(n) | Найти узел по номеру (нумерация с нуля) |
| `phlist_erase` | O(1) | Удалить узел из книги |
| `phlist_reposition` | O(n) | Переставить узел после изменения Ф.И.О. |
| `contact_cmp` | O(1) | Сравнить два контакта по Ф.И.О. |

Внутри всё собрано из двух вспомогательных функций (`static`, наружу не видны):

- `phlist_link_sorted` — вцепить готовый узел на его место по порядку
- `phlist_unlink` — отцепить узел из цепочки, не освобождая память

Отсюда:

```
phlist_insert     = malloc + link_sorted
phlist_erase      = unlink + free
phlist_reposition = unlink + link_sorted
```

Такое разделение убирает дублирование: логика перецепления указателей написана
ровно один раз, а не отдельно для вставки, удаления и перестановки.

### Как работает вставка

`phlist_link_sorted` идёт от головы, пока встречает контакты, которые меньше
или равны вставляемому, и останавливается на первом строго большем — узел
встаёт перед ним. Условие `<= 0` означает, что контакты с одинаковым Ф.И.О.
добавляются в конец своей группы, то есть порядок их добавления сохраняется.

Обрабатываются четыре случая, и именно они обычно ломаются:

| Случай | Что происходит |
|---|---|
| Список пуст | `head` и `tail` указывают на новый узел |
| Вставка в голову | обновляется `head`, у бывшей головы появляется `prev` |
| Вставка в середину | перецепляются четыре указателя соседей |
| Вставка в хвост | обновляется `tail`, у бывшего хвоста появляется `next` |

В коде это выражено через ветки `else`: если `node->prev == NULL`, значит узел
стал головой, и надо обновить `phlist->head`. Забытая ветка `else` — самая
частая причина «висячей головы», указывающей на освобождённую память.

### Почему нужен `phlist_reposition`

Ф.И.О. — ключ сортировки. Если отредактировать его прямо в узле, порядок
списка сломается молча: инвариант нарушен, но ни один вызов сразу не упадёт.
Поэтому после `editNames` меню вызывает `phlist_reposition`, который отцепляет
узел и вставляет обратно уже на новое место. Память при этом не
перевыделяется — переиспользуется тот же узел.

Правка номеров и соцсетей ключ не затрагивает, там перестановка не нужна.

### Освобождение памяти

`phlist_free` идёт по цепочке и **сохраняет `node->next` до вызова `free`** —
иначе следующий шаг читал бы уже освобождённую память. Принимает
`PhonebookList**`, чтобы обнулить указатель вызывающей стороны и не оставить
после себя висячий указатель.

## Меню

| Пункт | Действие |
|---|---|
| 1 | Добавить контакт — ввод Ф.И.О., до 4 номеров, до 4 соцсетей |
| 2 | Удалить контакт по номеру |
| 3 | Изменить контакт: Ф.И.О., соцсети, номера (правка и удаление) |

```
cd tests
make test
```

Часть функций объявлена `static`, поэтому тест включает `phoneBook.c` целиком.
Ввод подменяется файлом-фикстурой через `freopen` на `stdin`, вывод программы
глушится, чтобы отчёт Unity оставался читаемым.

Покрыты сравнение контактов, все четыре случая вставки и удаления, инварианты
цепочки `prev`/`next` после каждой операции, перестановка после правки Ф.И.О.,
заполнение тестовыми данными, ввод и редактирование контакта, удаление номеров
и соцсетей вместе с проверками границ.
