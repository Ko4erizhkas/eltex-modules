# 6.1 — Телефонная книга со статической библиотекой

Переработка 4.1: структуры и функции двухсвязного упорядоченного списка
вынесены в статическую библиотеку `libphonebook.a`, интерфейс остался
в программе.

## Сборка и запуск

```
make
./pb.exe
```

`make clean` убирает объектные файлы, библиотеку и exe.

## Файлы

| Файл | Куда попадает |
|---|---|
| `phoneBook.h` | Заголовок библиотеки: `Contact`, `PHNode`, `PhonebookList`, `contact_cmp`, `phlist_*` |
| `phoneBook.c` | Реализация списка → `libphonebook.a` |
| `menu.h`, `menu.c` | Ввод, редактирование, печать, тестовые данные, меню |
| `main.c` | Точка входа, настройка кодировки консоли |
| `tests/` | Юнит-тесты на Unity |

## Где проходит граница

В заголовке библиотеки осталось только то, что нужно списку. Пункты меню
(`MenuAction`, `EditAction`), число тестовых контактов и `print_interface`
переехали в `menu.h` — это интерфейс приложения, а не списка.

Связь односторонняя: `menu.c` включает `phoneBook.h`, обратно — нет.
Библиотека не знает ни про меню, ни про тестовые контакты.

## Сборка библиотеки

```
gcc -Wall -Wextra -c phoneBook.c -o phoneBook.o
ar rcs libphonebook.a phoneBook.o
gcc main.o menu.o -L. -lphonebook -o pb.exe
```

`ar rcs` — это просто архив объектных файлов: `r` заменить, `c` создать без
предупреждения, `s` записать индекс символов. На этапе компоновки нужные
объектные файлы вынимаются из архива и вшиваются в exe, поэтому после сборки
`libphonebook.a` можно удалить — программа продолжит работать. В задании 6.2
та же библиотека собирается разделяемой, и это перестаёт быть верным.

## Тесты

```
cd tests
make test
```

Тест собирается так же, как программа: подключает только `phoneBook.h` и
линкуется с `libphonebook.a`. Поэтому он проверяет не только логику списка, но
и саму библиотеку — при неверной сборке или отсутствии экспорта тест просто не
слинкуется. Библиотеку при необходимости соберёт `make -C ..`.

Покрыты сравнение контактов, создание и освобождение списка, вставка во все
четыре позиции (пустой список, голова, середина, хвост), сохранение порядка
добавления у одинаковых Ф.И.О., копирование контакта по значению, доступ по
индексу, удаление во всех позициях, перестановка после правки ключа и
согласованность цепочки `prev`/`next` после каждой операции.

Меню и ввод контактов в библиотеку не входят: они лежат в `menu.c`, с задания
4.1 не менялись и покрыты тестами там.
